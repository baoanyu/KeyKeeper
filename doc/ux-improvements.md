# KeyKeeper 易用性改进

> 生成时间：2026-07-23
> 相关文档：[audit-and-roadmap.md](audit-and-roadmap.md)（Bug 修复与路线图）· [KeyKeeper.md](KeyKeeper.md)（设计）· [../CLAUDE.md](../CLAUDE.md)
>
> 本文档聚焦**易用性 / UX 改进建议**，与 Bug 修复解耦。
> 触发场景：用户在 Volcano 火山方舟 Lite 套餐月度用量到 99%、剩余 33 天时才手动发现，暴露 KeyKeeper 作为菜单栏工具**未能主动帮助用户决策**。

---

## 触发场景（Why This Doc）

用户火山方舟控制台展示的信息 ✅：

- **套餐**：Lite 套餐，包月，剩余 33 天，自动续费已开
- **用量维度**：
  - 当前会话：7%（4h25min 后刷新）
  - 近 1 周：8%（3d 后刷新）
  - **近 1 月：99%（1d 后刷新）** ⚠️ 即将触顶
- **操作入口**：续费套餐 / 升级套餐

而用户**是通过手动点开控制台才发现的**，KeyKeeper 应该做但没做到：

1. 提前告警（80%、95% 分级）
2. 显示多维度用量（不只一个数字）
3. 显示套餐信息 + 剩余天数
4. 提供续费入口
5. 预测："按当前速率 X 天后触顶"

这些正是本文档要系统解决的。

## 1. 信息传达

**核心命题**：菜单栏应用不是"信息展示器"，是"状态指示器"。用户不该被迫解读数字。

### U-1. 数字化 vs 状态化

**现状**：显示"剩余 200 元"、"48.32 元"、"99%"—— 用户需要自己判断这是好还是坏。

**改进**：先给红/黄/绿信号，数字作为补充。托盘图标 + 每张卡片顶部一条状态条：

```
[绿] DeepSeek        剩余 48.32 元 (充足)
[黄] Volcano 月度    99% (即将触顶，1 天后刷新)
[红] Volcano 套餐    3 天后到期 (自动续费已关)
```

**依赖**：需要"阈值门槛"定义（见 U-11）。

---

### U-2. 相对时间盲区

**现状**：只有绝对数字"剩余 200 元"。

**改进**：加"按当前速率"预测

```
剩余 200 元 · 按 7 日均值可用 12 天
```

**决策价值**：比"剩余 200 元"大 10 倍——用户直接看到"要不要现在充"。

**实现依赖**：路线图 R-5（消耗速率与预测，SQLite 存快照）。

---

### U-3. 多维度盲区（Volcano 场景直接触发）

**现状**：一个 provider 一个卡片一个数字。**Volcano 至少有 3 个维度并存**（会话/周/月）。

**改进**：QuotaCard 支持一个 provider 多条 metric，堆叠显示

```
┌─ Volcano · Lite 套餐 (33 天剩余) ────────┐
│ 当前会话   [====      ] 7%   4h25 刷新  │
│ 近 1 周    [====      ] 8%   3d 刷新    │
│ 近 1 月    [==========] 99%⚠ 1d 刷新    │
│                                          │
│         [续费套餐]  [打开控制台]         │
└──────────────────────────────────────────┘
```

**依赖**：`QuotaInfo` v2 数据模型（`Vec<QuotaMetric>` + `Subscription`），详见 audit-and-roadmap.md P0-3 修复行动 2。**这是本文档所有其他改进的前置条件**。

---

### U-4. 刷新时机盲区

**现状**：用户看到 99% 会以为"随时超"，其实"1 天后刷新"。

**改进**：每条 metric 显示 `refresh_at` 相对时间

```
近 1 月 99% (1 天 06 时后刷新)
```

用户看到"再撑一天就好"，焦虑感立刻消失，甚至可以决定"这一天先用其他 provider"。

**实现依赖**：`QuotaMetric.refresh_at: Option<u64>`（audit-and-roadmap.md 数据模型 v2 中已包含）。

---

### U-5. 套餐信息盲区

**现状**：KeyKeeper 完全不显示套餐类型、剩余天数、自动续费状态。**这些是续费决策的关键**。

**改进**：QuotaCard 顶部 subscription 信息条

```
Volcano · Lite 套餐 · 包月 · 33 天剩余 · 自动续费 ✓
```

- 剩余 ≤7 天时，剩余天数变桔色
- 剩余 ≤3 天 + 自动续费关闭时，变红色
- 剩余天数点击可打开续费页

**实现依赖**：`Subscription` 数据结构（同 U-3）。

---

### U-6. 信任标注缺失

**现状**：用户看到 "48.32 元" 无法判断是"实时精确""缓存"还是"估算"。

**改进**：每张卡片右上角小图标

| 状态 | 图标 | 含义 |
|:---|:---|:---|
| 精确 | `⏱` | 5 分钟内刷新 |
| 缓存 | `📼` + "10min ago" | 网络失败但有历史数据 |
| 估算 | `≈` | 本地估算（如 Qoder 若仍无 API 时的降级方案） |

**依赖**：audit-and-roadmap.md `QuotaStatus` 枚举 + 路线图 R-2 缓存机制。

## 2. 决策路径

**核心命题**：显示"有问题"还不够，必须给"下一步做什么"。

### U-7. 低余额只是干瘪的橙字

**现状**：QuotaCard.vue 只是显示 "低额度" 三个字，没有下一步引导。

**改进**：低余额时展开"立即充值"按钮，点击 `shell::open` 到平台充值页

```
[黄] 剩余 8.5 元 (低)   [立即充值]
```

**依赖**：需要每个 provider 的充值 URL（audit-and-roadmap.md 数据模型 v2 中的 `QuotaInfo::console_url`）。

**注意**：这会**重新引入 `shell:allow-open` 权限**（audit-and-roadmap.md P1-4 建议移除）。取舍：为了 U-7 保留 shell 权限，仅允许白名单 URL（充值页固定 URL 集合），不允许任意 URL。

---

### U-8. 无平台控制台链接

**现状**：QuotaCard 双击、右键均无反应。

**改进**：点击卡片标题打开对应平台控制台

```
Volcano ↗    ← 点击标题跳转控制台
```

每个 PlatformSpec 加一个 `console_url` 常量（audit-and-roadmap.md P2-8 PlatformSpec 集中化的字段扩展）。

---

### U-9. 无对比视角

**现状**：4 张卡各自为政，用户不知道该用哪个。

**改进**：顶部加一栏"决策提示"

```
┌─ 决策提示 ─────────────────────┐
│ ⚠ Volcano 月度 99%，建议本月    │
│   优先使用其他 provider         │
│ 💡 DeepSeek 单价最低            │
└────────────────────────────────┘
```

**依赖**：单价数据（各 provider 每 M token 价格）需要硬编码在 PlatformSpec 里。

---

### U-10. 无历史对比

**现状**：只有当下数字。

**改进**：卡片右上角小 sparkline，显示最近 7 天余额趋势

```
Volcano 月度 99%    ▁▂▃▅▆▇█  ← sparkline
```

上升快 → 视觉红色告警。

**实现依赖**：路线图 R-5 SQLite 快照 + Vue sparkline 组件。

## 3. 主动性

**核心命题**：菜单栏应用的真正价值是"用户不来看我，我来提醒他"。

### U-11. 无阈值告警分级（Volcano 场景直接触发）

**现状**：只有单一"低额度"阈值。用户到 99% 才发现问题。

**改进**：三级告警门槛 + 图标颜色变化

| 门槛 | 触发 | 图标 | 通知 |
|:---|:---|:---|:---|
| Warning | 用量 ≥ 80% | 黄点 | 无 |
| Alert | 用量 ≥ 95% | 红点 | 系统通知 |
| Critical | 用量 ≥ 99% 或 套餐 ≤ 3 天 | 红闪 | 系统通知 + 音效 |

**依赖**：audit-and-roadmap.md P0-3 修复行动 4（告警门槛）+ P2-1 通知接入。

**去抖动**：同一 metric 同一门槛 24 小时只通知一次，避免打扰。

---

### U-12. 无用量突增告警

**现状**：用量线性缓慢增长和突然 3× 增长视觉上一致。

**改进**：过去 7 天用量基线 + 检测突增

```
if 近 24h 用量 > 过去 7 天日均 × 3:
    发送通知："Volcano 近 24h 用量突增（日均 8% → 今日 26%）"
```

**依赖**：路线图 R-5 SQLite 快照。

**价值**：能发现"Key 被泄露/滥用"的第一信号，安全价值巨大。

---

### U-13. 无套餐到期告警

**现状**：完全无。

**改进**：套餐剩余 ≤7 天 / ≤3 天 / ≤1 天 分级通知

```
剩余 7 天 → "Volcano Lite 套餐将在 7 天后到期"
剩余 3 天 + 自动续费关闭 → "⚠ Volcano 套餐 3 天后到期，自动续费已关闭"
```

**依赖**：audit-and-roadmap.md 数据模型 v2 中的 `Subscription.expires_at` 和 `auto_renew`。

---

### U-14. 无预测告警

**现状**：用户到 99% 才发现，KeyKeeper 从未预警。

**改进**：基于消耗速率预测触顶时间

```
if 按当前速率预测触顶时间 < 3 天:
    通知："Volcano 月度用量预计 3 天内触顶（当前 85%，日增 5%）"
```

**依赖**：路线图 R-5 消耗速率。

**这是 U-11 的时间维度补充**——U-11 是"到 80% 才告警"，U-14 是"按速率预测提前告警"，二者互补。

## 4. 添加流程

**核心命题**：新用户的第一分钟决定留存。

### U-15. Key 从哪里来

**现状**：AddProviderForm.vue 光秃秃一个 password 输入框，用户不知道 Key 从哪里拿。

**改进**：选择 provider 后，输入框下方显示获取链接

```
选择: Volcano
API Key: [                    ]
        ↳ 如何获取？打开火山方舟控制台 → API Key 管理
```

**依赖**：PlatformSpec 加 `key_docs_url` 字段。

---

### U-16. Key 格式无校验

**现状**：填任何字符串都能保存，错了才在刷新时报 401。

**改进**：前端根据 PlatformSpec 的正则校验

| Provider | Key Pattern | Placeholder |
|:---|:---|:---|
| DeepSeek | `^sk-[a-f0-9]{32,}$` | `sk-xxxxxxxx...` |
| Volcano | 待抓 API 后定 | 待抓 API 后定 |
| ZhipuAI | `^[a-f0-9]{32}\.[A-Za-z0-9]+$` | `xxxxxxxx.xxxxxxxx` |

错误时红框提示 "Key 格式看起来不对"。允许 override（用户点"继续"仍能提交，防止我们的正则不完备）。

---

### U-17. 无隐私说明

**现状**：用户不敢把 Key 填进一个不熟悉的 App。

**改进**：AddProviderForm 底部显示

```
🔒 你的 API Key 存储在 macOS Keychain 中，KeyKeeper 永不上传。
   源代码开源：github.com/xxx/keykeeper
```

小改动，信任度大幅提升。

---

### U-18. 不支持批量导入

**现状**：4 个平台要点 4 次"添加"。

**改进**：AddProviderForm 加"从 `.env` 导入"按钮

- 粘贴 `.env` 内容
- 自动识别 `DEEPSEEK_API_KEY=sk-xxx` / `VOLC_API_KEY=xxx` 之类
- 支持撤销

**成本**：中等，但对 4 个 Key 齐飞的用户来说大幅降低摩擦。

---

### U-19. 首次使用无引导

**现状**：新用户打开是空白页 + "还没有添加平台，请在上方添加"。

**改进**：3 步引导

```
Step 1/3: 选一个你要监控的 AI 平台
[DeepSeek] [Volcano] [ZhipuAI] [Qoder]

Step 2/3: 打开 XX 控制台，复制 API Key
（配图：控制台截图 + 高亮 API Key 位置）

Step 3/3: 粘贴 Key，KeyKeeper 会自动开始查询
```

**成本**：高，但显著提升 GitHub star → daily active 转化。

**建议时机**：1.0 之前做。

## 5. 错误恢复

**核心命题**：出错不可避免，但用户要能自救。

### U-20. 401 无操作入口

**现状**：QuotaCard 显示 "HTTP 401: xxx"，用户不知道怎么办。

**改进**：错误信息旁加动作按钮

```
❌ Volcano: HTTP 401 (Key 无效或已过期)
   [重新配置 Key]  [打开控制台]
```

点"重新配置 Key" → 展开 AddProviderForm 表单，provider 已选好。

---

### U-21. 网络失败无重试

**现状**：某个 provider 网络失败，只能等下次 5 分钟自动刷新，或者手动全量刷新。

**改进**：卡片右上角"↻"按钮，单卡重试

**依赖**：audit-and-roadmap.md 路线图 R-4（单卡刷新）。

---

### U-22. 无 Key 有效性预检

**现状**：AddProviderForm 保存后要等 refresh() 完成才知道 Key 对不对。

**改进**：Add 按钮改为"验证并保存"，先调一次 API

```
点击 "验证并保存"
  → 显示 "正在验证..."
  → 成功: "✓ Key 有效，余额 48.32 元"，然后保存
  → 失败: "✗ HTTP 401，请检查 Key 是否正确"
```

失败时不保存到 Keychain，避免脏数据。

## 6. 快捷操作

**核心命题**：高频使用要能"闭眼操作"。

### U-23. 无右键菜单

**现状**：QuotaCard 只有一个 "✕" 删除按钮。

**改进**：右键卡片弹出

```
· 立即刷新此平台
· 打开控制台
· 立即充值
· 复制余额到剪贴板
· 查看历史用量
· 临时隐藏（下次刷新恢复）
· 永久删除
```

---

### U-24. 菜单栏 hover 无预览

**现状**：必须点开窗口才能看余额。菜单栏应用应该做到"扫一眼菜单栏就知道"。

**改进**：托盘图标 tooltip 显示最紧张平台

```
悬停托盘图标 →
┌─────────────────────────┐
│ KeyKeeper               │
│ ⚠ Volcano 月度 99%      │
│ 3 个平台正常            │
└─────────────────────────┘
```

**实现**：Tauri 的 `TrayIconBuilder::tooltip()`，动态更新。

---

### U-25. 无键盘快捷键

**现状**：全鼠标操作。

**改进**：
- `⌘R` 刷新全部（窗口打开时）
- `⌘⇧1/2/3/4` 打开对应平台控制台
- `⌘⇧K` 全局快捷键 toggle 窗口（audit-and-roadmap.md R-7）
- `Esc` 关闭窗口

## 7. Top 5 优先级建议

如果只能改 5 个（假设 audit-and-roadmap.md 数据模型 v2 已完成）：

| 排序 | 项 | 理由 | 依赖 |
|:---|:---|:---|:---|
| 1 | **U-3 多维度用量** | Volcano 场景直接触发，从"能用"到"真的可靠" | 数据模型 v2 |
| 2 | **U-11 阈值分级告警**（80/95/99） | 一次到位解决"用户忘了看"的核心问题 | audit-and-roadmap P0-3 修复行动 4 + P2-1 |
| 3 | **U-5 套餐信息展示** | 剩余天数是续费决策关键，完全缺失 | 数据模型 v2 |
| 4 | **U-7 + U-8 充值 / 控制台入口** | 从"显示状态"升级到"引导行动" | PlatformSpec 加 url 字段 |
| 5 | **U-15 Key 引导文档链接** | 新用户上手门槛骤降 | PlatformSpec 加 docs_url 字段 |

**这五项做完**，KeyKeeper 从"能查余额的工具"升级到"能主动管理 AI 支出的助手"。
